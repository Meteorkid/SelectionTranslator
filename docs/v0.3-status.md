## 已知缺陷与风险

1. **Chrome 扩展依赖外部协议**：首次点击会弹“是否允许打开划词翻译”，用户拒绝后不会自动降级。没有本地 HTTP server 是刻意保持轻量；后续若要做无提示桥接，需要增加 127.0.0.1 server 和来源校验。
2. **屏幕录制权限**：`screencapture -i` 需要用户在系统设置中手动授权；未授权时只提示，不弹系统请求。剪贴板图片 OCR 不受此限制。
3. **系统翻译语言包**：首次可能触发系统下载窗；取消后显示原文和错误，不会卡死。
4. **Chrome 扩展安装验收**：已在干净测试 profile 完成 CDP 加载 + 浮标 + 点击 + App 接收的端到端验收；用户日常 Chrome 仍需按 README 的“加载已解压扩展”手动安装一次，才能持久启用。
5. **Anki/CSV**：AnkiConnect 已用 mock 验证；CSV 仅代码审查，未做 UI 保存回归。
6. **发布**：无 Developer ID、未公证、未接自动更新；`dist/` 产物需在最终构建后生成。
7. **测试覆盖**：没有 XCTest target；当前是构建 + 手工端到端验证，和 Easydict 的 59 个测试文件仍有差距。

## 结论

v0.3 已经把“上下文优先 + 本地降级 + 轻量账户/历史 + 浏览器/悬浮入口 + Anki”做成可运行的完整链路。P1 的核心交互已验证；P2 的文档上下文与 Anki 已验证；P3 的 Chrome/悬浮入口已实现。真正阻止“发布级完成”的是外部条件（屏幕录制授权、Chrome 日常安装、Developer ID 公证）和少量未回归项，而不是主链路代码。
